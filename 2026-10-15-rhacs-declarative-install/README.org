#+TITLE: Advanced cluster security installation
#+DATE: <2026-10-15 Thu>
#+AUTHOR: James Blair


This document captures the steps required to set up an instance of Red Hat Advanced Cluster Security on OpenShift ~4.20+~ using declarative, gitops friendly resource manifests.


* TODO Log in to cluster

This guide assumes you already have an OpenShift cluster. Let's start by logging in as the cluster admin. Define variables for ~OCP_API_URL~, ~OCP_USERNAME~ and ~OCP_PASSWORD~ in a ~.env~ file in the base of this directory before running the commands below:

#+NAME: Login to openshift cluster
#+begin_src bash
source .env
oc login "${OCP_API_URL}" --username "${OCP_USERNAME}" --password "${OCP_PASSWORD}" --insecure-skip-tls-verify
#+end_src


* [X] Deploy rhacs

Once we are logged in to our cluster, we can use the steps below to install Red Hat Advanced Cluster Security.

** [X] Install rhacs operator

We'll install Advanced Cluster Security through it's operator, by creating the required ~Subscription~ and ~OperatorGroup~ resources, within our chosen ~rhacs-operator~ namespace.

#+NAME: Install rhacs operator
#+begin_src bash
oc apply --filename rhacs/operator.yaml
#+end_src

#+RESULTS: Install rhacs operator
#+begin_example
namespace/rhacs-operator created
operatorgroup.operators.coreos.com/rhacs-operator created
subscription.operators.coreos.com/rhacs-operator created
#+end_example


** [X] Deploy rhacs central

Once the operator is installed we can deploy ~central~. [[https://docs.redhat.com/en/documentation/red_hat_advanced_cluster_security_for_kubernetes/4.11/html/installing/installing-rhacs-on-red-hat-openshift][Central]] is the core management interface, API and data persistence component for Advanced Cluster Security.

#+NAME: Deploy central
#+begin_src bash
oc apply --filename rhacs/central.yaml
#+end_src

#+RESULTS: Deploy central
#+begin_example
namespace/stackrox created
central.platform.stackrox.io/stackrox-central-services created
#+end_example


** [X] Log in to rhacs

With central deployed, we can log in via the passthrough ~route~ with the default ~admin~ username and the password sourced from the generated ~secret~.

#+NAME: Rhacs login
#+begin_src bash
xdg-open "https://"$(oc get route --namespace stackrox central --output jsonpath='{.spec.host}')

echo $(oc get secret --namespace stackrox central-htpasswd --output jsonpath='{.data.password}' | base64 --decode) | wl-copy
#+end_src

#+RESULTS: Rhacs login
#+begin_example
#+end_example


** [X] Secure cluster

With central deployed and running we can now deploy the stackrox secured cluster services. One central instance can secure many different clusters.

#+NAME: Secure cluster
#+begin_src bash
oc apply --filename rhacs/secured.yaml
#+end_src

#+RESULTS: Secure cluster
#+begin_example
serviceaccount/acs-cluster-registration created
clusterrole.rbac.authorization.k8s.io/acs-cluster-registration created
clusterrolebinding.rbac.authorization.k8s.io/acs-cluster-registration created
job.batch/acs-cluster-registration created
securedcluster.platform.stackrox.io/local created
#+end_example


* TODO Automated gitops install

With the initial installation process validated in a step by step fashion, we can now proceed to automate the entire process using a [[https://www.redhat.com/en/topics/devops/what-is-gitops][gitops]] methodology.

** TODO Install gitops operator

On OpenShift, the supported gitops tooling is [[https://argo-cd.readthedocs.io/en/stable/][ArgoCD]], which is installed via **OpenShift GitOps** operator.

Let's install ArgoCD now by creating the required ~Subscription~ and ~OperatorGroup~ resources.

#+NAME: Install gitops operator
#+begin_src tmux
oc apply --filename gitops/operator.yaml
#+end_src


** TODO Install rhacs via gitops

With argocd installed, we can create an ~Application~ resource to tell our cluster to keep our rhacs manifests in sync on our cluster.

#+NAME: Create rhacs application
#+begin_src tmux
oc apply --filename gitops/application.yaml
#+end_src

With those steps completed, we now have a declarative installation of Red Hat Advanced Cluster Security that will be continually enforced by our ArgoCD instance 🎉
